## 验证内容

输入上一版本实际产出的本地合成控件设计包，将其中 variables.css 应用到前端测试页，再创建故意偏离的副本。合成页面用于稳定验证验收器，不作为新的真实品牌网站测试；v2.1 的 24 站记录保持为历史结果。

设计文档 SHA-256：`bfed83b159bc39276c45d4e662890eb1b140d77cb2b466e08ee9caf9604f2615`。

每个普通场景按 1440×1000 / 390×844 测量 12 项约束，共 24 项；分别采集默认、弹窗展开、下拉展开、键盘焦点四种场景。检查实际标题/字段、弹窗与遮罩、下拉面板、checkbox 的代理绘制及 progress 的主题色。弹窗截图保持实际视口，默认状态使用全页截图。

偏离页的五类偏差在两个视口分别检出：标题颜色、标题字体、字段文字色、弹窗圆角、下拉面板圆角。正确的 token 仍在页面中，但没有掩盖这些实际绘制问题。

本地已复核桌面/手机默认与展开截图。故意改变的手机标题还产生了明显的换行和层次变化：原设计文档没有标题字阶，不把这个尺寸自动纳入“文档明确约束”的失败数；将其记作参考缺口。若验收目标是原页面复刻，应补充对应原图/原站后再判断。

原文档未定义本次对应的间距、布局、图片验收约束，三个维度保持未覆盖，不把 24/24 转换成整体 100% 还原。19 类控件虽可在页面清单中出现，本次自动样本只覆盖其中部分绘制与状态；完整键盘行为、系统选择窗口、屏幕阅读器和浏览器差异仍需专项验证。

## 自动回归

原 44 项测试，加上七组验收回归，共 **51 项**：

1. 期望值必须来自当前文档；拒绝未知/歧义 token、重复映射、不合理容差和任意状态动作。
2. 显式像素容差，不掩盖颜色或单位差异。
3. 正常页面在两个视口的实际字体、布局、弹窗/遮罩、下拉、hover、键盘焦点与真实视口截图。
4. 正确变量未应用、错误颜色/间距、手机偏差，以及计算字体列表匹配但实际字体缺失。
5. 隐藏元素、不存在/模糊选择器、未绘制伪元素与没有直接文字的继承容器保持受阻。
6. 相对单位经过变量引用后仍需要上下文；不同现代颜色表达不直接误判为不同颜色。
7. 原生 JS 业务弹框失败；提交型触发器受阻，未提交表单。

测试仅依赖本地 HTTP fixture 与浏览器，不依赖实时品牌站。可复现资料：[验收 fixture](../tests/fixtures/fidelity.md)、[回归测试](../tests/fidelity.test.mjs)、[操作规则](../references/fidelity.md)、[场景记录](fidelity-v2.3.json)。

验收器的通过只针对已映射的约束。未检查项不算通过；颜色上下文、字体别名、图片和构图等无法确定的部分保留证据并交由视觉复核，不输出虚构的整体还原度分数。
